# Photonix project agreements

- Read the Photonix Requirements.txt checklist and ARCHITECTURE.md when planning work. The official problem statement takes precedence. Keep every mandatory workflow in scope across releases. SolarFit is the primary additional differentiator.
- Work in the Desktop Odoo-SIMS folder using local Odoo 20 and PostgreSQL. Ask for the user's permission before every GitHub action.
- Start each proposed feature with the profession using it, the recurring failure, the decision or handoff it changes, and a measurable outcome. Describe one example a judge could follow. For mandatory features, simplify the implementation while preserving the requirement.
- If an idea duplicates data, adds another tool or service without a demonstrated need, slows the main workflow, or has no clear user and outcome, flag the drift to the user. Explain which objective it affects and propose the smallest in-scope alternative before expanding.
- Enforce permissions on the server. Give each profession an appropriate queue and protect customer, supplier, financial, and personnel data.
- Label estimates and demo fixtures clearly. Claim actual savings or improvements only from recorded transactions and a defensible baseline.
